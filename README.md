# 对比度调色板求解器（Contrast Palette Solver）

一个基于 **Node.js + Express + 原生前端** 的 Web 应用：导入颜色令牌、候选色和
WCAG 前景/背景最小对比度约束，系统在全部可行方案中进行**全局分支定界搜索**，
依次最小化：

1. **改色令牌数**（尽量不动原令牌）；
2. **CIE Lab 总色差**（CIEDE2000，改动尽量小）；
3. 以**令牌名与色值字典序**稳定决胜（结果唯一、可复现）。

可锁定任意令牌（锁定后只能保持原色）。页面展示每条约束的**改前 / 改后对比度**；
无解时列出**锁定颜色直接造成的冲突**。支持导出替换后的令牌 JSON。

> 数据仅在本机内存中处理，不写入磁盘、不访问任何外部服务。

## 唯一启动命令

```bash
docker compose up --build
```

启动后用浏览器打开：

```
http://localhost:3000
```

停止：在终端按 `Ctrl+C`，或另开终端执行 `docker compose down`。

> 容器构建时会自动执行 `npm install` 准备依赖，无需手动安装。

## 输入格式

在页面文本框粘贴 JSON，或点击“导入 JSON 文件”。

```json
{
  "tokens": [
    { "name": "bg", "value": "#ffffff" },
    { "name": "text", "value": "#767676" }
  ],
  "candidates": ["#101828", "#374151", "#6b7280", "#ffffff"],
  "constraints": [
    { "fg": "text", "bg": "bg", "minContrast": 4.5 }
  ],
  "locked": ["bg"]
}
```

- `tokens`：颜色令牌，`name` 唯一，`value` 为 `#rgb` / `#rrggbb` 十六进制色。
  每个令牌的取值域 = **候选色 ∪ 自身原色**（原色永远可选，从而“不改”是合法选择）。
- `candidates`：全局候选色池。
- `constraints`：约束 `foreground/background` 对比度至少为 `minContrast`
  （按 WCAG 相对亮度公式 `(L1+0.05)/(L2+0.05)` 计算；常用 4.5 / 3 / 7）。
- `locked`：可选，锁定令牌名列表，锁定的令牌不会被改变。

**输入上限**：10 个令牌、12 个候选色、30 条约束。

## 示例数据

仓库 `examples/` 目录提供两份示例，也可在页面一键载入：

- [`examples/sample.json`](examples/sample.json) — **可解示例**：浅底文字令牌
  对比度不足，求解器仅把不达标令牌改为候选色中色差最小的深色；
- [`examples/sample-unsat.json`](examples/sample-unsat.json) — **无解示例**：
  `bg` 与 `brand` 被锁定，候选池中不存在满足 7:1 的 `brand/bg` 颜色，
  结果区会列出该锁定冲突（含当前比值与候选色下最佳可达比值）。

## 输出与导出

- 每个令牌：原色 → 结果色、ΔE2000 色差、保持 / 改色 / 已锁定状态；
- 每条约束：改前 → 改后对比度、是否满足；
- 点击 **“导出替换后的令牌 JSON”** 下载扁平的 `{ "令牌名": "#色值" }` 文件。

## 工作原理（简述）

- sRGB → 线性 RGB → XYZ(D65) → CIE Lab；色差用 CIEDE2000；
- 预计算所有“颜色 × 颜色”对比度矩阵，搜索中 O(1) 增量校验约束；
- 分支定界按“约束度数高的令牌优先、原色取值优先”的顺序搜索，
  以 `(改色数, 总色差, 方案字典序)` 做上界剪枝；
- 求解前先做锁定诊断：两端或一端锁定时，枚举该约束下所有可达颜色对，
  若最佳可达对比度仍低于要求，则作为“锁定直接造成的冲突”列出。
